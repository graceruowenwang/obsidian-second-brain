PARA 是 [[SecondBrain|第二大脑]] 方法论中用于组织数字信息的四层文件架构，按行动性递减排列为 Projects（项目）、Areas（领域）、Resources（资源）和 Archives（归档）。

## 核心架构与定义

PARA 由 Tiago Forte 在其著作《Building a Second Brain》中提出，旨在解决传统按主题分类的笔记系统难以检索和复用的问题。其四个层级定义如下：

- **Projects（项目）**：具有明确目标和截止日期的短期努力，例如“完成Q2报告”或“策划产品发布会”。这是系统中行动性最强的层级，所有项目一旦完成即可归档。
- **Areas（领域）**：需要持续维护的长期责任范围，如“健康”、“财务”或“职业发展”。领域没有截止日期，需要定期关注和投入。
- **Resources（资源）**：持续感兴趣的主题或参考材料，如“设计思维”、“心理学”或“摄影”。这一层级按兴趣而非行动性组织。
- **Archives（归档）**：以上三类中不再活跃的内容，包括已完成的项目、过去的兴趣或不再相关的领域。归档不是删除，而是储备以备未来参考。

> [原创] 一个关键洞察是：PARA 的排序反映了从“行动”到“参考”的递进关系。项目和领域是你当前关注的，资源和归档是为未来准备的。这种设计避免了传统分类法中“所有信息平权”导致的检索困难。

## 设计哲学与原则

PARA 的设计体现了 [[CODE|CODE 方法论]] 中“按可行动性组织”的核心原则：

- **行动性递减排列**：Projects 离你最近，Archives 离你最远。这种排列确保你每天首先看到的是需要立即处理的工作，而非分散注意力的参考资料。
- **跨平台通用性**：同一结构可应用于所有数字工具（云盘、笔记应用、邮件），无需为不同工具设计不同分类。
- **可流动性**：信息可以在四个类别之间自由移动。例如，项目完成后归入 Archives；兴趣变成责任则从 Resources 升级到 Areas。这种流动性避免了“一次分类，永久固定”的僵化。

> [原创] 与传统 [[Zettelkasten|卡片盒笔记法]] 强调“按概念组织、无预设分类”不同，PARA 更强调“按行动性分类”。两者并不矛盾：PARA 管理的是“项目文件和行动材料”，Zettelkasten 管理的是“概念卡片和知识沉淀”。两者可以并行使用，用 PARA 管做什么，用 Zettelkasten 管知道什么。

## 与中间包的关系

PARA 系统与 [[IntermediatePackets|中间包]] 概念紧密相关。中间包是任何“半成品”形态的知识片段（如一段话、一张幻灯片、一个图表），它们是大型作品的构建块。PARA 通过按行动性组织信息，使得中间包可以在不同项目间被高效复用：

- **模块化**：每个中间包是自包含的独立单元，可独立存储于 Resources 或 Projects 中。
- **可复用**：在 Projects 中创建的中间包，项目完成后可归档至 Archives，未来新项目启动时可直接调用。
- **知识复利**：中间包在不同项目间的复用，产生了类似金融资本的复利效应，打破了“每次都从零开始”的低效模式。

## 实践建议与局限性

- **从项目开始**：不要试图一次性建立完美的 PARA 系统。先从当前最重要的项目开始，逐步扩展。
- **每周回顾**：花 30 分钟整理和移动信息，确保分类反映当前优先级。
- **避免过度分类**：PARA 只有四个顶层文件夹，不要创建过多子分类。如果某个子分类超过 20 个条目，考虑将其升级为独立的领域或项目。
- **结合 [[MapOfContent|内容地图 (MOC)]]**：PARA 提供行动导向的组织，MOC 提供概念导向的导航。两者结合可以同时满足“行动效率”和“知识探索”的需求。
