**CODE 方法论**是由 Tiago Forte 在其著作《构建第二大脑》中提出的四步知识管理工作流，包含捕获（Capture）、组织（Organize）、提炼（Distill）和表达（Express）四个连续阶段，旨在将碎片化信息转化为可复用的知识资产。

## 核心四步工作流

CODE 方法论的核心是将知识管理从被动的信息存储转变为主动的知识创造循环。每个阶段都有明确的输入、输出和操作原则。

### C — Capture（捕获）

捕获阶段的目标是从各种信息源（文章、书籍、对话、播客）中有选择性地收集有价值的信息。核心原则是“捕获有共鸣的内容”，而非试图记录一切。关键判断标准是：这条信息是否引起了我的共鸣？它是否改变了我的想法？这与 [[Zettelkasten|卡片盒笔记法]] 中“用自己的话写”的理念一脉相承，强调主动筛选而非被动复制。

### O — Organize（组织）

组织阶段使用 [[PARA|PARA 系统]] 将捕获的信息分类存储。PARA 按行动性递减排列为四个层级：项目（Projects）、领域（Areas）、资源（Resources）和归档（Archives）。这种组织方式打破了传统的按主题分类模式，使信息直接服务于行动。例如，一个关于“设计思维”的笔记不会存放在“设计”文件夹中，而是根据其当前用途——是用于一个具体项目（Projects）、属于持续关注的领域（Areas）、还是作为参考材料（Resources）——来决定位置。

### D — Distill（提炼）

提炼阶段通过 [[ProgressiveSummarization|渐进式总结]] 技术，逐步从原始笔记中提取精华。该技术采用四层结构：原始笔记（100%内容）→ 加粗（约20%）→ 高亮（约5%）→ 执行摘要（1-2句话）。关键原则是“按需提炼”：不是所有笔记都需要处理到最深层，而是根据笔记的重要性和未来复用可能性灵活处理。这体现了 [[EvergreenNotes|常青笔记]] 中“持续生长”的理念——笔记的价值在于演化而非一次完成。

### E — Express（表达）

表达阶段是将组织好的知识用于创造新作品（文章、演示、项目、决策）。这是 CODE 循环的最终输出环节，也是知识价值实现的时刻。核心理念是：**知识的价值不在于存储，而在于被重新利用和组合。** 表达的结果可以是任何形式的“[[IntermediatePackets|中间包]]”——一段话、一张幻灯片、一个图表、一条引用，这些半成品模块可以在不同项目中反复复用，产生知识复利效应。

## 设计哲学与原则

CODE 方法论背后蕴含着一套关于知识本质和认知效率的深刻洞察。

### 知识服务于行动

CODE 的设计哲学是“知识应该服务于行动”。信息的组织方式应该反映它的可行动性，而不是它的学科归属。这与 [[ProductivityParadox|生产力悖论]] 的解决思路一致：不是收集更多信息，而是让已有信息更有效地转化为行动。PARA 系统的“按行动性递减排列”正是这一原则的具体体现。

### 从存储到连接

CODE 方法论的核心转变是将知识管理从“存储”转向“连接”。散落的笔记就像没有索引的图书馆——信息都在，但找不到。真正有价值的是概念之间的链接，而不是概念本身。这与 [[LinkingYourThinking|LYT 方法论]] 和 [[MapOfContent|内容地图 (MOC)]] 的理念高度一致：通过建立笔记之间的链接，让知识在不同时间、不同项目之间流动、组合和增值。

### 复利效应

良好组织的知识片段可以在新项目中反复使用，每次复用都产生新的价值。CODE 方法论通过“捕获→组织→提炼→表达”的循环，将知识工作从“每次都从零开始”的低效模式转变为“持续积累和复用”的高效模式。这种复利效应在 [[MethodologyFusion|方法论融合]] 的背景下尤为显著——不同方法论的组合使用可以产生更大的协同价值。

## 实践建议与局限性

### 实践建议

- **从捕获开始，但不要止于捕获**：很多人只做 Capture，忽略了后续的 Organize、Distill 和 Express。完整的 CODE 循环才是有效的知识管理。
- **为未来的自己而写**：笔记的读者是三个月后完全忘了当时想法的自己。用那时候的你能理解的方式写。
- **每周花 30 分钟回顾和整理**：定期维护是 CODE 系统持续有效的关键。
- **不要追求完美分类**：让分类随需求演化，而非一次性设计完成。

### 局限性

- **对工具依赖较强**：CODE 方法论的有效性高度依赖于数字工具的支撑，如笔记应用、标签系统等。
- **学习曲线较陡**：PARA 分类和渐进式总结需要一定时间适应和熟练。
- **可能过度结构化**：对于某些创造性工作，过于严格的工作流可能限制灵感的自由流动。
- **与 AI 时代的适配**：在 [[AiAssistedCoding|AI 辅助编程]] 和 [[LLMWiki|LLM Wiki 方案]] 兴起的背景下，CODE 的某些手动操作（如手动提炼、手动分类）可以被 AI 自动化，但核心的“知识服务于行动”原则依然有效。
