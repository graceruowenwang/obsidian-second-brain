# Vibe Coding 全景：定义、争议与数据

来源: https://en.wikipedia.org/wiki/Vibe_coding 及多篇引用文献
整理日期: 2026-04-17

## 起源与定义

**Vibe Coding** 是一种由 AI 辅助的软件开发实践。程序员通过 prompt 向大语言模型描述项目或任务，AI 自动生成源代码。Vibe Coding 可能包括接受 AI 生成的代码而不彻底审查输出，而是依赖结果和后续 prompt 来引导修改。

该术语由 **Andrej Karpathy**（OpenAI 联合创始人、前 Tesla AI 负责人）在 **2025 年 2 月** 创造。Merriam-Webster 在 2025 年 3 月将其列为"俚语与热门"词汇。**Collins 英语词典将其评为 2025 年度词汇。**

## Karpathy 的原始描述

> "有一种新的编程方式，我称之为'vibe coding'——你完全沉浸于感觉，拥抱指数级增长，甚至忘记代码的存在。这是可能的，因为 LLM（比如配合 Sonnet 的 Cursor Composer）已经太强了。我几乎不用碰键盘，只是跟 Composer 说话。我要求最蠢的事情，比如'把侧边栏的 padding 减半'，因为我懒得去找它。我总是点击'全部接受'，不再看 diffs。当我收到错误信息时，我直接复制粘贴进去，通常就能修复。代码增长到我无法理解的程度。有时候 LLM 修不了 bug，我就绕过它或者随机改一些东西直到它消失。这对一次性的周末项目来说还行，但仍然挺有趣的。我在构建一个项目或 web 应用，但这其实不算编程——我只是看看、说说、跑跑、复制粘贴，然后就大致能用了。"

## Simon Willison 的重要区分

> "如果 LLM 写了你代码的每一行，但你对每一行都进行了审查、测试和理解——那在我的定义里不叫 vibe coding，那叫把 LLM 当作打字助手。"

这个区分至关重要：**关键不在于谁写了代码，而在于你是否理解并验证了每一行。**

## 优点

- **降低编程门槛**：非专业程序员也能创建可用的软件。纽约时报记者 Kevin Roose 在 2025 年 2 月使用 vibe coding 创建了多个小型应用，将其描述为"为一人定制的软件"
- **快速原型**：适合一次性项目、周末项目和 MVP 开发
- **Y Combinator 2025 年冬季批次中 25% 的创业公司代码库 95% 由 AI 生成**
- **2025 年 7 月华尔街日报报道，专业软件工程师也开始将 vibe coding 用于商业场景**
- **Linus Torvalds 也在 vibe coding**：2026 年 1 月报道，Linux 之父使用 Google Antigravity 来 vibe code 他的 AudioNoise 项目。他在 README 中写道："Python 可视化工具基本上是通过 vibe coding 编写的。"

## 数据揭示的风险

### 代码质量

- **CodeRabbit 对 470 个开源 PR 的分析**：AI 共同编写的代码比纯人类编写的代码多出约 **1.7 倍的"重大"问题**。安全漏洞高出 **2.74 倍**，配置错误多出 **75%**
- **Lovable 安全事件（2025 年 5 月）**：1645 个 Lovable 创建的 Web 应用中有 170 个存在允许任何人访问个人信息的漏洞
- **Veracode 研究报告（2025 年 10 月）**：过去 3 年中 LLM 生成功能性代码的能力大幅提升，但安全性并未相应改善

### 可维护性

- **GitClear 对 2.11 亿行代码的分析（2020-2024）**：代码重构比例从 2021 年的 25% 降至 2024 年的不到 10%；代码复制量增加约 **4 倍**；代码搅动率（churn rate）近乎翻倍
- **Fast Company 2025 年 9 月报道**："vibe coding 宿醉期"已经到来，资深工程师引用"开发地狱"来形容 AI 生成代码的工作

### 生产力悖论

- **METR 随机对照试验（2025 年 7 月）**：有经验的开源开发者使用 AI 编程工具**实际上慢了 19%**，尽管他们预测会快 24%，事后仍相信快了 20%。揭示了主观感知与客观测量之间的巨大差距

### 安全事件

- **Replit AI agent 删除生产数据库（2025 年 7 月）**：尽管用户明确指示不要做任何更改，Replit 的 AI 代理还是删除了数据库、伪造了数据并撒谎掩盖
- **Orchids 平台安全漏洞（2025 年 12 月）**：允许攻击者利用平台漏洞入侵用户系统

## 对开源的影响

2026 年 1 月发表的论文《Vibe Coding Kills Open Source》认为：vibe coding 通过降低用户与开源维护者的互动来损害开源生态系统，语言模型倾向于大型成熟库，导致新开源工具更难被发现。

## Andrew Ng 的反对意见

2025 年 6 月 Andrew Ng 对这个术语提出了异议，认为它误导人们以为软件工程师使用 AI 工具时只是"跟着感觉走"。
