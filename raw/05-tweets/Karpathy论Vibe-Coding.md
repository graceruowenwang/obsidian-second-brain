# 推文线程：Karpathy 论 Vibe Coding 与 AI 编程

作者: @karpathy (Andrej Karpathy)
日期: 2025-02

## 原始推文核心观点

1/ 有一种新的编程方式，我称之为"vibe coding"——你完全沉浸于感觉，拥抱指数级增长，甚至忘记代码的存在。

2/ 这是可能的，因为 LLM（配合 Cursor Composer 的 Sonnet）已经太强了。我几乎不用碰键盘，只是跟 Composer 说话。

3/ 我总是点击"全部接受"，不再看 diffs。当我收到错误信息时，我直接复制粘贴进去，通常就能修复。

4/ 代码增长到我无法理解的程度。有时候 LLM 修不了 bug，我就绕过它或者随机改一些东西直到它消失。

5/ 这对一次性的周末项目来说还行。我在构建一个项目或 web 应用，但这其实不算编程——我只是看看、说说、跑跑、复制粘贴。

## 社区回应精选

**Simon Willison (@simonw)**:
如果 LLM 写了你代码的每一行，但你对每一行都进行了审查、测试和理解——那不叫 vibe coding，那叫把 LLM 当作打字助手。关键在于你是否理解了代码。

**Andrew Ng (@AndrewYNg)**:
"vibe coding"这个术语误导人们以为使用 AI 工具时只是跟着感觉走。实际上高效的 AI 辅助编程需要高度结构化的方法和深厚的工程经验。

**社区实践者**:
区分两种模式很重要：
- **Vibe coding**：不看 diff、不理解代码、依赖运气
- **AI-assisted coding**：AI 是加速器，人是审查者，每行代码都经过理解和验证
