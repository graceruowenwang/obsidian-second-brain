# 上线评估与路径规划

> 日期: 2026-04-19
> 基于完整代码审阅、功能矩阵分析和竞品对比

---

## 一、诚实判断：当前不能直接上线

核心产品逻辑是完整的，但距离 Obsidian 社区商店的发布标准还有差距。以下是具体分析。

---

## 二、付费/免费边界：需要调整

### 当前边界

| 免费功能 | Pro 功能 ($5/月, $49/年) |
|----------|--------------------------|
| 核心编译（增量+全量） | 自动编译 |
| Wiki 浏览（卡片/搜索） | AI 对话（免费3条/月） |
| 单文件编译 | SVG 思维导图 |
| DeepSeek 模型 | 多 LLM 后端 |
| Draft/Review 工作流 | 自定义模板 |
| 批量审核 | 向量检索配置 |
| 3条免费对话/月 | 健康检查 |

### 问题诊断

**问题1：免费层太慷慨，Pro 层不够痛**
- 核心价值（编译+浏览）完全免费，用户没有升级动力
- 自动编译是"便利性"而非"必要性" -- 手动点一下不是大痛点
- AI 对话 3 条/月太少，不够形成习惯，但也恰好说明用户需要它

**问题2：付费墙与用户价值错位**
- 自定义模板是高级用户的刚需，但它被锁在 Pro 里
- 向量检索配置应该免费 -- 不配 embedding 就自动降级为关键词检索（已实现），何必锁配置入口

**问题3：缺少"钩子功能"**
- 没有一个功能让免费用户深度体验后感到"不能没有"
- 最强的钩子应该是 AI 对话（让人和知识库对话的体验是不可逆的），但 3 条太少

### 建议调整

```
免费层（保持）:
  - 核心编译（增量+全量+单文件）
  - Wiki 浏览（卡片+搜索+反向链接）
  - DeepSeek 模型
  - Draft/Review 工作流
  - 健康度仪表板（新增 P0）

免费层（调整 -- 从 Pro 降下来）:
  - 向量检索配置 -- 这是基础功能，不配就降级
  - 自定义模板 -- 高级用户的核心需求，限制使用反而降低内容质量

Pro 层（核心付费点 -- 刚需）:
  - AI 对话（无限）+ 主动洞见推送
  - 自动编译（真正的便利性刚需）
  - SVG 思维导图 + 知识图谱分析
  - 编译历史 + 间隔式复习提醒
  - 多 LLM 后端
```

### 定价建议

当前 $5/月、$49/年偏贵。Obsidian 社区插件用户的付费意愿在 $2-4/月区间。

```
建议定价:
  月付: $3.99/月
  年付: $29.99/年（约 $2.5/月，节省 37%）
  终身: $79.99（一次性买断，限量发售）
```

## 三、上线前的硬性阻碍

### 必须修复（P0）

1. **README 不符合 Obsidian 社区商店格式**
   - 缺少英文 README（社区商店要求英文）
   - 缺少截图/GIF 演示
   - 缺少与 Obsidian API 兼容性声明

2. **manifest.json 缺少必要字段**
   - 需要英文 description（当前是中文）
   - `isDesktopOnly: true` 需要合理解释（fetch 依赖）

3. **首次使用体验不完整**
   - Setup Wizard 存在但缺少成功反馈
   - 编译完成后没有"下一步"引导
   - 空状态（wiki 为空）的引导已经存在但不够突出

4. **错误处理不够健壮**
   - API 超时/限流有基本处理，但缺少用户友好的恢复建议
   - 编译失败后没有"诊断"机制（哪个 token 导致 JSON 解析失败？）

### 应该修复（P1）

5. **缺少版本迁移机制**
   - CompileCache 结构变化时没有迁移逻辑
   - 用户升级插件后可能遇到兼容性问题

6. **缺少日志持久化的清理机制**
   - log.md 会无限增长
   - 应该只保留最近 N 条

7. **缺少卸载清理指南**
   - 用户卸载后 wiki/ 和 raw/ 文件还在，但 plugin data 丢失
   - README 中应说明数据所有权

## 四、竞品对比：你的差异化在哪

| 维度 | Second Brain | Smart Connections | Copilot |
|------|-------------|-------------------|---------|
| 核心理念 | 编译（Compile） | 检索（RAG） | 辅助（Assist） |
| 知识结构 | 自动生成 Wiki 结构 | 不改变原有结构 | 不改变原有结构 |
| AI 角色 | 编译器 + 对话伙伴 | 搜索引擎 | 写作助手 |
| 输出物 | 结构化知识库 | 搜索结果 | 文本补全 |
| 知识积累 | 有状态（编译累积） | 无状态（每次检索） | 无状态 |

**核心差异化一句话**：其他插件是"帮你找笔记"，你是"帮你把笔记变成知识"。

这个差异化是有价值的，但需要通过 README 和演示视频讲清楚。

## 五、上线路径规划

### 阶段一：Alpha 测试（1-2 周，当前）

## 六、一句话结论

**产品哲学是深刻的，技术底座是扎实的，但上线不是技术问题而是体验问题。** 当前最需要做的不是加功能，而是让一个完全陌生的用户能在 5 分钟内完成：安装 -> 配置 API -> 编译素材 -> 看到 Wiki -> 感到"卧槽，这是我的知识库？"

这个"啊哈时刻"才是上线的真正标准。
