# 优化步骤建议

> 日期: 2026-04-19
> 前置: 03-上线评估与路径规划.md
> 原则: 每个步骤独立可交付，按用户价值排序

---

## 核心判断

当前最该做的事不是加功能，而是**消除用户从安装到"啊哈时刻"之间的所有摩擦**。一个用户打开插件后 5 分钟内的体验决定了产品生死。

以下步骤按优先级排序，每步都有明确的代码改动点。

---

## 步骤 1：修复首次编译后的"下一步"引导

**问题**: 编译完成后，用户看到一堆数字（3 概念 + 1 实体 + 2 来源），但不知道接下来该做什么。没有任何引导告诉他们"去 Wiki 预览看你的知识库"。

**改动点**:
- `src/views/compile-view.ts` -- `renderCompileSummary()` 末尾新增一个引导按钮
- 编译成功后，在摘要区域下方显示："编译完成！点击查看你的知识库" -- 跳转到 Wiki View

**预期效果**: 用户编译完立即看到成果，形成正向反馈闭环。

---

## 步骤 2：Setup Wizard 增加第 4 步"放入素材"

**问题**: 当前 Wizard 到第 3 步就结束了。用户不知道 raw/ 目录在哪、该放什么文件。

**改动点**:
- `src/ui/setup-wizard.ts` -- 在 Step 2（目录创建）和 Step 3（完成）之间插入新步骤
- 新步骤内容：
  1. 显示已创建的目录结构和每个子目录的用途说明
  2. 提供一个"加载示例素材"按钮，将 `raw-sample/` 的内容复制到 `raw/`
  3. 或者提供"跳过，稍后添加"选项

**预期效果**: 用户知道第一步该做什么，且可以零成本试用。

---

## 步骤 3：调整免费/Pro 功能边界

**问题**: 当前向量检索配置和自定义模板被锁在 Pro，但它们影响输出质量；定价偏高。

**改动点**:
- `src/core/feature-gate.ts` -- 从 `PRO_FEATURES` 集合中移除 `"embedding-config"` 和 `"advanced-templates"`
- `src/ui/settings-tab.ts` -- 取消这两个配置项的 Pro 门控
- `src/core/i18n/zh-CN.ts`, `en.ts`, `ja.ts` -- 更新功能对比文案
- `src/ui/license-settings.ts` 或 `src/views/compile-view.ts` -- 价格调整为 $3.99/月、$29.99/年

**预期效果**: 免费用户能获得更好的编译质量（embedding + 模板），Pro 的核心卖点聚焦在 AI 对话、自动编译、思维导图。

---

## 步骤 4：英文 README + manifest.json 规范化

**问题**: Obsidian 社区商店要求英文描述；当前 README 只有中文。

**改动点**:
- 新建 `README.en.md`（或在 README.md 中双语展示）
- 关键内容：一句话定位、截图/GIF、快速开始、功能列表、免费/Pro 对比
- `manifest.json` -- description 改为英文
- 准备 1-2 张截图：编译前（raw 素材）vs 编译后（Wiki 知识库）

**预期效果**: 满足社区商店提交的基本要求。

---

## 步骤 5：Wiki View 空状态增加示例引导

**问题**: 当前空状态只说"Wiki 为空，请先编译素材"。但用户可能连素材都没有。

**改动点**:
- `src/views/wiki-view.ts` -- `renderIndex()` 的空状态区域（L455-465）扩展为三步引导：
  1. "放入素材到 raw/ 目录" -- 显示目录结构和链接到 raw 文件夹
  2. "点击编译" -- 按钮直接触发编译
  3. "浏览你的知识库" -- 编译后自动跳转
- 如果检测到 `raw-sample/` 存在但 `raw/` 为空，显示"加载示例素材"按钮

**预期效果**: 空状态不再是死胡同，而是清晰的操作路径。

---

## 步骤 6：编译错误恢复增强

**问题**: 当 API 返回格式异常时，用户只看到"编译失败"，没有可操作的恢复建议。

**改动点**:
- `src/core/compile.ts` -- `runAnalysis()` 中 JSON 解析失败时，记录原始返回的前 200 字符到错误信息
- `src/views/compile-view.ts` -- `userFriendlyError()` 增加更多场景：
  - "AI 返回内容为空，可能是模型不支持 JSON 输出，请检查模型名称"
  - "分析结果为空，可能是素材内容过短或语言不匹配"
- 编译失败时增加"诊断建议"按钮，显示最近一次 API 调用的状态码和响应摘要

**预期效果**: 用户遇到错误时能自助解决，而不是直接放弃。

---

## 步骤 7：log.md 自动清理

**问题**: log.md 无限增长，长期用户会积累大量无用日志。

**改动点**:
- `src/core/file-utils.ts` -- `writeLogEntry()` 修改：写入前检查条目数量，超过 200 条时只保留最近 100 条
- 清理逻辑：读取 log.md，按 `## [日期]` 分割，保留最后 100 段

**预期效果**: log.md 大小可控，不影响性能。

---

## 步骤 8：版本迁移机制

**问题**: CompileCache 结构变化（如新增 compileHistory）后，旧版本用户升级可能出错。

**改动点**:
- `src/types.ts` -- `CompileCache` 增加 `version` 字段（已存在，当前为 1）
- `src/core/file-utils.ts` -- `emptyCache()` 中设置新版本号
- `src/core/compile.ts` -- 加载缓存后增加版本检查：
  ```
  if (cache.version < 2) {
    // 迁移：补全缺失字段
    cache.compileHistory = cache.compileHistory || [];
    cache.version = 2;
  }
  ```
- 当前改动：将版本号从 1 升到 2，补全 compileHistory

**预期效果**: 用户升级插件无感，不丢失数据。

---

## 实施优先级

| 顺序 | 步骤 | 预计工时 | 价值 |
|------|------|----------|------|
| 1 | 编译后"下一步"引导 | 1h | 消除核心体验断裂 |
| 2 | Setup Wizard 加载示例素材 | 2h | 零成本试用 |
| 3 | 免费/Pro 边界调整 | 1h | 商业模型优化 |
| 4 | 英文 README + manifest | 3h | 社区商店必需 |
| 5 | Wiki 空状态引导 | 1.5h | 减少用户迷失 |
| 6 | 编译错误恢复 | 2h | 降低流失率 |
| 7 | log.md 自动清理 | 0.5h | 长期维护 |
| 8 | 版本迁移机制 | 1h | 升级兼容性 |

建议按 1-2-3 先做（4h 完成核心体验修复），然后 4-5-6（6.5h 完成上线准备），最后 7-8（1.5h 收尾）。

**总计约 12 小时工作量。**
